CV-BTN — Design System

Botao base sem variante

.cv-btn sem modificador de variante: inline-flex, pill, 44px de altura, padding 16px, font-weight 700, cursor pointer. Base sobre a qual todas as variantes constroem sua identidade visual.

Base .cv-btn Base

Sem variante de cor — herda apenas a estrutura. Na pratica sempre use uma variante (--primary, --secondary, etc.).

Form Actions

Acoes de formulario

cv-btn--primary para confirmar; cv-btn--secondary para cancelar. O botao de maior peso fica sempre mais a direita.

Navigation Actions

Acoes de navegacao

cv-btn--back retorna ao contexto imediato (pagina anterior). cv-btn--back-list retorna ao indice do modulo (nivel acima). Ambos sao discretos por design — nunca competem com o CTA principal.

Voltar — contexto imediato Navegacao

Retorna a pagina anterior na stack de navegacao. Visual discreto: fundo muted, borda suave, cor neutra.

Voltar para lista — nivel acima Navegacao

Retorna ao indice do modulo (ex: lista de oficios, lista de viagens). Levemente mais sutil que --back; cor muted com hover em azul-secundario.

Navegacao entre etapas (wizard) Wizard

Etapas de wizard: voltar usa cv-btn--back; avancar usa cv-btn--primary.

Document Actions

Acoes documentais com identidade propria

Cada formato documental tem cor exclusiva: teal (#0e7c9e) para visualizar, vermelho-documental (#b42318) para PDF, azul-arquivo (#1a5498) para DOCX. Nunca usar o mesmo cinza generico para todos.

Acoes documentais completas Document

Preview: consulta neutra (teal). PDF: identidade forte (vermelho-documental). DOCX: distinto do primary do sistema (azul-arquivo). Baixar: acao secundaria neutra. Gerar: acao operacional neutra.

Tool Actions

Acoes de ferramentas operacionais

cv-btn--tool e para operacoes que executam calculos, consultas ou modificacoes de estado sem ser CTA principal nem destrutivas. Visual discreto: fundo muted, sem sombra, hover em azul-suave.

Ferramentas operacionais Tool

Acoes que nao sao CTA nem destrutivas: calcular, tracar rota, limpar filtros, aplicar filtros.

Destructive Actions

Excluir x Remover

A diferenca visual comunica o grau de risco antes do clique. Fill vermelho sinaliza acao irreversivel no banco. Outline danger sinaliza remocao local e reversivel.

Excluir vs Remover — lado a lado Perigo

Excluir = acao permanente sobre registro do banco. Fill vermelho solido + sombra colorida — maximo peso visual. Remover = remocao local no formulario, reversivel. Outline danger mais sutil — sem fill, borda colorida.

Excluir com contexto de confirmacao Perigo

Par canonico de confirmacao: cancelar secundario + excluir danger.

Remover em linha de lista Sutil

Remocao contextual dentro de uma linha de item — outline danger discreto.

Regras de Uso

Checklist do sistema cv-btn

Regras obrigatorias para uso correto do sistema de botoes.

Regras de uso Referencia
Regra Detalhe
Sempre use uma variante .cv-btn sem variante nao tem cor; adicione --primary, --secondary, etc.
Excluir vs Remover --danger para registro no banco (irreversivel); --soft-danger para remocao local (reversivel).
Hierarquia por pagina Maximo um --primary por grupo de acao. Multiplos --primary na mesma area = ausencia de hierarquia.
Icones sempre com aria-label cv-btn--icon sem aria-label e inacessivel. Nunca omitir.
Sem style="" inline Toda personalizacao via classe. Inline styles quebram o design system.
Sem onclick="" inline Comportamento via JS externo com data-attributes. Nao misturar JS no HTML.
Tamanho por contexto md (default) para formularios; sm para cards e toolbars; lg apenas para CTAs de alta prominencia.
Namespace separado .cv-btn e o novo sistema. .btn e o sistema legado das paginas reais. Nao misturar nas paginas reais ainda.

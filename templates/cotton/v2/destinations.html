{% cotton:vars cities_url estados extra_class id list_id managed rows template_id title %} {% comment %} Destinos v2 — a seção completa: linhas de estado e cidade, adicionar, remover e reordenar por arraste. ## Usar É só isso. A seção busca os próprios dados (`core/templatetags/destinos.py`), liga o próprio motor e já nasce com uma linha. Nada precisa ir para a view, e nenhuma tela precisa de script próprio. `id` existe para as telas cujo script próprio ainda procura a seção pelo id — `js/pages/termos-form.js` faz isso para copiar o destino do ofício vinculado. Sem ele a seção renderiza e a cópia para de acontecer, sem erro nenhum. `list_id` e `template_id` são a mesma história do `id`, um nível abaixo: o editor de roteiro procura a LISTA (`destinos-container`) e o MOLDE (`tmpl-destino-roteiro`) por id, porque reindexa as linhas e clona o molde por conta própria — ele faz mais coisa com os destinos do que as outras telas (recalcula trechos, rota e diárias a cada mudança). Sem eles a seção renderiza e o editor não acha o que reindexar. `estados` e `cities_url` existem para quem tiver motivo para contrariar a busca automática — uma tela que filtre estados, por exemplo. Fora isso, não passe: são as duas linhas que, esquecidas, faziam a seção renderizar bonita e não funcionar. ## O que ela emite O contrato de `js/components/location-rows.js`: a seção (`data-location-rows`), a lista (`data-location-list`), o molde (`template[data-location-template]`) que o JS clona, e o `data-api-cidades-url` da cascata estado → cidade. `data-location-managed` pede que o motor se ligue sozinho — sem isso, cada tela precisava chamar `initManagedRows` no próprio script, que é como as 4 telas legadas ainda fazem. `:managed="False"` desliga essa auto-ligação, e existe por um defeito medido: o editor de roteiro JÁ liga o motor por conta própria (ele precisa disso para recalcular trechos, rota e diárias a cada mudança de destino), e com os dois ligados **um clique em "+" inseria DUAS linhas**. Só desligue aqui quem já chama `initManagedRows`; desligar sem substituto deixa a seção sem motor nenhum, e ela renderiza igual. Trocar o nome de qualquer um desses ganchos desliga a seção EM SILÊNCIO: a página não dá erro, os campos só param de responder. O legado equivalente (`cotton/travel/destination_section.html`) declara 44 variáveis para os mesmos ganchos, quase todas repassadas por `include` de quatro níveis. {% endcomment %} {% load destinos %}

{% cotton:vars cities_url estados extra_class id rows title %} {% comment %} Destinos v2 — a seção completa: linhas de estado e cidade, adicionar, remover e reordenar por arraste. ## Usar É só isso. A seção busca os próprios dados (`core/templatetags/destinos.py`), liga o próprio motor e já nasce com uma linha. Nada precisa ir para a view, e nenhuma tela precisa de script próprio. `id` existe para as telas cujo script próprio ainda procura a seção pelo id — `js/pages/termos-form.js` faz isso para copiar o destino do ofício vinculado. Sem ele a seção renderiza e a cópia para de acontecer, sem erro nenhum. `estados` e `cities_url` existem para quem tiver motivo para contrariar a busca automática — uma tela que filtre estados, por exemplo. Fora isso, não passe: são as duas linhas que, esquecidas, faziam a seção renderizar bonita e não funcionar. ## O que ela emite O contrato de `js/components/location-rows.js`: a seção (`data-location-rows`), a lista (`data-location-list`), o molde (`template[data-location-template]`) que o JS clona, e o `data-api-cidades-url` da cascata estado → cidade. `data-location-managed` pede que o motor se ligue sozinho — sem isso, cada tela precisava chamar `initManagedRows` no próprio script, que é como as 4 telas legadas ainda fazem. Trocar o nome de qualquer um desses ganchos desliga a seção EM SILÊNCIO: a página não dá erro, os campos só param de responder. O legado equivalente (`cotton/travel/destination_section.html`) declara 44 variáveis para os mesmos ganchos, quase todas repassadas por `include` de quatro níveis. {% endcomment %} {% load destinos %}

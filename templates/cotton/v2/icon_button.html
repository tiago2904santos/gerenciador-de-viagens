{% cotton:vars aria_label autosave_link extra_class hook href icon menu_id menu_src target tone tooltip tooltip_tone type %} {% comment %} Icon button v2 — ação sem rótulo, em forma circular. Não é uma variante do `button`: aquele é retangular e existe para carregar texto. Aqui a forma é redonda e o rótulo vive no `aria-label`, que é OBRIGATÓRIO — sem ele a ação não existe para quem usa leitor de tela. `menu_id` transforma o botão no gatilho de um `menu` com o mesmo id. Os três atributos (`data-overlay-trigger`, `-kind`, `-target`) são contrato do `js/components/overlay.js`; declará-los aqui, e não soltos pelo chamador, evita o defeito que já custou caro nesta migração — a marcação parece certa, a tela renderiza e o botão simplesmente não abre nada. `tooltip_tone="accent"` pinta a caixinha do tooltip no accent — o `icon-tooltips.js` lê isso de `data-tooltip-tone`. Serve para a ação que precisa se anunciar, como a que só aparece quando o ponteiro entra no campo. `menu_src` é a variante `PF-04`: o corpo do menu não vai no HTML da lista, vem do servidor no primeiro clique. `hook` é o atributo `data-*` que liga o botão a um motor JS, pelo mesmo motivo do `c-v2.button`: o gancho é contrato do JS, e declarado aqui não muda de nome sem que alguém veja. `autosave_link` preserva o formulário antes de uma ação que navega para outro cadastro. O valor `1` é contrato de `autosave.js` e de scripts de página. `type="submit"` é para a ação que vive DENTRO de um formulário — excluir um anexo, por exemplo. Sem ele o botão nasce `type="button"` e o clique não submete nada: a tela não dá erro, o botão só não faz. `target="_blank"` abre o destino noutra aba; vale só para o botão-link, e vem com `rel="noopener noreferrer"`, que a aba nova exige para não receber o controle desta. {% endcomment %} {% load icones %} {% if href %} {% icone_svg icon %} {% else %} {% endif %}

{% cotton:vars attrs current_name current_remove_url current_view_url description doc_label extra_class kinds_json signed title url %} {% comment %} Item de menu que abre o diálogo de anexar o documento assinado. É um componente próprio, e não um `menu_item` com atributos soltos, porque os CINCO ganchos abaixo são contrato do `js/components/attach-signed-modal.js`: é deles que o diálogo tira para onde enviar o arquivo, o que mostrar como já anexado e por onde removê-lo. Um nome trocado não dá erro — o item abre um diálogo vazio. `kinds_json` é o caso de VÁRIOS documentos anexáveis: um payload JSON com um objeto por tipo (`key`, `option_label`, `doc_label`, `url` e, se houver assinado, `current_name`/`current_view_url`/`current_remove_url`). Com dois ou mais, o diálogo mostra o toggle de seleção; com um, ele fica oculto. Aqui o valor SAI escapado no HTML e isso está certo: quem lê é `getAttribute`, que devolve o texto já decodificado — diferente do `hook`, onde o escape estraga o nome do atributo. O rótulo muda com o estado: sem assinado é "Anexar", com assinado é "Gerenciar", porque as ações disponíveis passam a ser outras. `title` e `description` existem para a prestação, onde o item anexa TRÊS documentos diferentes ("RT, diário ou comprovante") e o rótulo genérico mentiria sobre o que o diálogo abre. `attrs` repassa os ajustes de diálogo que só algumas telas fazem — a chave de reabertura, os tipos de arquivo aceitos, os rótulos dos botões. São contrato do mesmo script, mas opcionais: sem eles o diálogo usa os padrões dele. Ficam soltos em vez de virarem seis parâmetros porque quem os lê é `getAttribute`, e declará-los aqui não acrescentaria checagem nenhuma. Os cinco atributos do documento ÚNICO só saem com `url`: quem tem `kinds_json` descreve cada documento dentro do payload, e emiti-los vazios punha cinco `data-*` sem conteúdo no HTML de todo card de prestação. {% endcomment %} {% load icones %}

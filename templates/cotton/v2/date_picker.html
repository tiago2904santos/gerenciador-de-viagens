DELEGA ao partial global `cotton/ui/forms/date_picker.html`, que é o único ponto de verdade da marcação do calendário — há um teste de contrato para isso (`test_calendar_markup_exists_only_in_the_global_partial`), e ele me pegou: a primeira versão deste componente recriou o markup, o que reintroduzia exatamente a divergência que o partial existe para impedir. O v2 acrescenta só o invólucro `.date-field`, para a folha `static/css/v2/date-picker.css` vestir o campo sem alcançar as telas legadas. `start_field`/`end_field` são os `BoundField` do formulário. Passá-los faz o calendário escrever nos campos ocultos que o Django vai ler no POST — sem eles o componente é só um seletor de tela, que mostra a data e não salva nada. `start_hidden_name`/`end_hidden_name` são a alternativa para quem NÃO tem formulário: o filtro de uma lista, que manda os valores por querystring. Um ou outro, nunca os dois. O JS é o `js/components/date-picker.js`, achado pelo partial. {% endcomment %}
